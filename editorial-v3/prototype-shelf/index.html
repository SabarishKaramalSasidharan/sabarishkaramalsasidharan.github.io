Why I built Prototype Shelf

As I built more prototypes with AI, demo links accumulated in Slack. An old message could point to a newer build than the one I’d shared for review.

I built the Shelf as a single source of truth for my design work. Each project keeps its demos, saved versions, and review notes together so product and engineering can return to the same build at handoff.

Data 360 example

How product and engineering review a prototype

Product managers and engineers find a project from the Shelf’s index. They can filter for work that needs review and open the demos from the same project record.

I give reviewers a task to try in the Walkthrough tab. For Semantic Clustering, Start demo takes a product manager or engineer straight to the flow for transforming a text field and trying auto-grouping.

The Versions tab shows the live prototype and past builds, with change notes and links to open them. Product and engineering can reopen the exact version they reviewed, like v2, after a newer demo is published.

Product and engineering leave feedback from the item they’re reviewing. For the variable selector shown here, “Comment on this” opens a GitHub issue with the project and enhancement already filled in.

How I share AI practices with the design team

I regularly share what works in my AI-assisted prototypes, from starting with shared components to giving reviewers a task to try and saving the build they review.

I turned the Shelf into a template so other designers could use the same workflow. Designers on my team, including my principal designer, now use it.

Automations

Open the right flow and capture feedback

Prototype Shelf

The Shelf filters work by review status and archives approved and shipped projects. It builds guided demo links and pre-fills GitHub issues with the flow or proposed change under review.

Publish a review build

Prototype Shelf and Semantic Clustering

The Shelf and the prototype each have their own Pages build and deploy commands. Semantic Clustering’s scripts also prepare icon assets for local preview and publishing.

Keep a reviewable snapshot

Semantic Clustering

The prototype’s freeze script publishes a copy of the build at a versioned URL. I add the link and change notes to the Shelf’s version history and choose which version to mark current.

Run project checks

Semantic Clustering and the starter

Both include checks for architecture, imports, and theme assets. They include a pre-push hook that can run the code checks once installed. The starter also tests its lint rules.

Generate review material

Semantic Clustering and the starter

Both can generate component stories and build Storybook. The starter also has commands to refresh component specs and prepare Storybook for Pages.

Sync skills and reuse components

Semantic Clustering and the starter

Semantic Clustering has scripts to sync skills and check for starter changes. The starter provides the Port Pack scripts that package and import reusable components.
